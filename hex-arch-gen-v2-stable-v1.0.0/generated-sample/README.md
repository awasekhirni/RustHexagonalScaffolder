# generated-api

Hexagonal-architecture REST API generated by **hex-gen v2** (db-first) from
the PostgreSQL schema `public`.

* HTTP framework: **axum** 0.7 (async, tokio)
* Persistence: **SQLx** 0.8 (runtime-checked queries, no ORM)
* API docs: **OpenAPI 3** via utoipa — served at `/swagger-ui`
* Patterns: **Enterprise Bus** + typed per-entity repositories
* Observability: **tracing** (structured, JSON-capable)
* Concurrency: **ETag / If-Match** optimistic locking (when `version` col detected)
* Pagination: offset + cursor (`?cursor=<b64>&limit=N`)
* Security: JWT auth, security headers, RLS-aware queries (when `tenant_id` detected)

## Run

```bash
cp .env.example .env      # or edit the generated .env directly
cargo run
# Swagger UI  → http://localhost:8080/swagger-ui
# OpenAPI doc → http://localhost:8080/api-docs/openapi.json
```

> **Live API docs.** v0.5.0 (closes G-L03): the OpenAPI 3.1 document
> served at the URL above is generated at boot from the
> `#[utoipa::path]` attributes on every handler, then upgraded to
> 3.1 at serve-time by `api::openapi::to_3_1()`. Point your
> OpenAPI-3.1-compatible client (Postman, Insomnia, Stoplight) at
> that URL — no offline copy needed.

## Migrations

```bash
make migrate              # applies migrations/*.sql to $DATABASE_URL
# or:
psql $DATABASE_URL -f migrations/*.sql
```

## Architecture

```
api/                       OpenAPI document + Swagger UI
application/               use-case services, DTOs, ports (bus, repository)
domain/                    pure business entities and value objects
infrastructure/            PostgreSQL and in-process bus adapters
presentation/              axum REST handlers, routes, middleware, state
shared/                    cross-cutting error and pagination types
core/                      typed IDs, value objects, Clock, UoW, saga, chaos, bulkhead, shutdown
patterns/                  idempotency, outbox, cursor pagination, retry, breaker, webhooks, cache, flags, load shed
security/                  JWT, RBAC, PII redaction, security headers, tenancy, GDPR, secrets
config/                    strongly-typed settings (config crate)
logging/                   tracing init
telemetry.rs               OTLP + Prometheus (stubs)
```

Every write goes through the application service, every read through the
same service; handlers depend only on trait-object ports, so the SQLx
adapters are swappable without touching business logic.

## Regeneration

Edit the schema, re-run the generator with `--force`, and the artefacts
are refreshed. Manual edits inside generated files will be lost —
extend the generator templates instead.
